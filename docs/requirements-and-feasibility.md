## 2. 先講結論

1. **整體可行，但工程量很大，風險集中在「植被」和「程序化車輛造型」兩處。**
2. **畫面目標比聽起來容易達到**：《地平線 4》本身並沒有光線追蹤，它靠的是優秀的美術、預烘焙光照、立方體貼圖反射和調色。也就是說，光追對本項目是「加分項」，在 M3/A17 Pro 以上設備上可以做到**超過**地平線 4 的反射質量。
3. **「函數繪製」和「低性能要求」本來是矛盾的**——每幀都即時計算噪聲函數非常昂貴。解決的核心思路是：
   **「函數只負責生成，不負責每幀渲染」**：生成一次 → 烘焙成網格／紋理快取 → 之後像普通資源一樣渲染。安裝包小，執行時效率接近傳統遊戲。
4. **真實感樹葉可以做到**，方法是「程序化單片葉子 + 分層 LOD + 執行時自動生成遠景替身（Impostor）」，下文詳述。
5. **建議硬件分級**：
   - 完整光追檔：M3 及以上 Mac、iPhone 15 Pro（A17 Pro）及以上（有硬件光追單元）
   - 標準檔（無光追，畫面接近地平線 4 中檔）：M1/M2、A15/A16
   - 更舊設備不支援

## 3. 技術鏈路評估

### 3.1 引擎選型

| 方案 | 優點 | 缺點 | 結論 |
|---|---|---|---|
| **自研引擎（C++/Swift + Metal）** | 完全控制程序化管線；可深度使用 Metal 光追、Mesh Shader、MetalFX；包體最小 | 工作量最大，需要圖形學經驗 | **推薦** |
| Unreal Engine 5 | Lumen/Nanite/PCG 現成；Nanite 植被 | Mac/iOS 上 Lumen/Nanite 支援和性能不理想；包體大；程序化「全函數」並非其設計方向 | 備選 |
| Unity (HDRP/URP) | 上手快 | HDRP 不支援 iOS；URP 畫質上限不足 | 不推薦 |

推薦自研的理由是：本項目最大的特點（全程序化 + Apple 專屬優化）恰好是商業引擎最不擅長的。
建議結構：C++20 核心 + `metal-cpp`，平台層與 UI 用 Swift；著色器用 Metal Shading Language。

### 3.2 渲染主架構

- **Visibility Buffer / GPU Driven 管線**：Mesh Shader（Metal 3 起支援 Object/Mesh Shader）做簇級（cluster）視錐剔除、遮擋剔除（Hi-Z）。這是支撐海量植被的基礎。
- **Apple TBDR 架構優化**：善用 tile memory、memoryless 渲染目標，減少頻寬——對 iPhone 的功耗和發熱影響非常大。
- **低解析度渲染 + 超分**：MetalFX Temporal Upscaling（內部 50–67% 解析度），新系統可加 MetalFX 幀插值與降噪超分（Denoised Upscaler，可直接處理光追噪點）。
- **浮動原點（Floating Origin）+ 雙精度世界座標**：大世界必需，避免遠處抖動。

### 3.3 光照與光線追蹤（用戶最願投入的部分）

| 效果 | 光追檔（M3+/A17 Pro+） | 標準檔 |
|---|---|---|
| 車身反射 | **硬件光追反射**（1/4~1/2 解析度 + 時域降噪），反射中包含周圍車輛、樹木、地形 | 車周動態立方體貼圖（每幀更新一面，6 幀輪換）+ SSR，這正是地平線 4 的做法 |
| 環境反射 | 光追 + SSR 混合 | SSR + 反射探針 |
| 全局光照 | DDGI 探針（光追更新）或 ReSTIR 類方案 | 天光 + 程序化環境光遮蔽 + 低頻探針 |
| 陰影 | 近處光追陰影（柔和、接觸陰影準確），遠處級聯陰影 | 級聯陰影 / 虛擬陰影貼圖 |
| 環境光遮蔽 | RTAO | GTAO（螢幕空間） |

**車漆材質**（與光追同等重要）：多層 BRDF——底漆 + 金屬薄片（程序化法線噪聲產生閃點）+ 清漆層（Clearcoat）+ 可選珍珠漆薄膜干涉。這一部分完全函數化，零貼圖。

**光追降成本的關鍵技巧**：
- 光追場景（加速結構 BLAS/TLAS）使用**簡化代理幾何**：樹在光追世界中用低模、不透明替身，避免昂貴的 alpha 測試。
- 只對高光滑度表面（車身、玻璃、濕路面、水面）發射反射光線；粗糙表面回退到探針。
- 每像素 ≤ 0.5 條光線，靠時域累積 + MetalFX 降噪補足。
- 靜態世界的 BLAS 按區塊生成後快取，只有車輛每幀更新 TLAS。

**天空與大氣**：物理大氣散射（預計算 LUT）、光線步進體積雲（3D 噪聲——天然就是「函數繪製」）、高度霧、體積光。這部分是程序化方案的強項，能用很低成本做出極佳的觀感。

### 3.4 地形

- **生成**：多層分形噪聲（fBm）+ 域扭曲（Domain Warping）+ GPU 侵蝕模擬（水力/熱力侵蝕），產生真實的山谷、河道、沖積扇。侵蝕是讓程序化地形「不像噪聲」的關鍵。
- **渲染**：幾何 Clipmap 或 CDLOD 四叉樹，遠處自動減面。
- **材質**：根據坡度、高度、濕度、侵蝕流量自動混合岩石／泥土／草地／沙；程序化 PBR 材質烘焙進**執行時虛擬紋理（RVT）快取**，只在鏡頭附近生成高精度，生成一次反覆使用。
- **道路**：樣條曲線（Spline）生成路網，道路對地形做「切挖/填方」，路面材質、車道線、路肩、磨損痕跡全部程序化。
- 評估：**成熟技術，可行性高**。

### 3.5 植被（最大難點）

#### 3.5.1 樹
1. **枝幹生成**：Space Colonization（空間殖民演算法）為主，L-System 為輔。前者能長出自然、不規則、互相避讓的樹冠，比純 L-System 真實得多。按樹種提供參數集（橡樹、松樹、樺樹、楓樹…）。
2. **樹皮**：程序化樹皮紋理（裂紋 Voronoi + 噪聲），烘焙到快取。
3. **單片葉子**：用函數描述葉形輪廓（葉尖、葉基、鋸齒、葉脈），程序化生成葉片紋理：反照率 + 法線（葉脈凸起）+ 透光度 + 光滑度。每樹種 3–5 種葉片變體，全部執行時生成。
4. **葉片排佈**：葉片按葉序規則掛在末梢小枝上，而不是拼成一團球——這是擺脫「兒童動畫感」的根本。
5. **光照**：葉片雙面透光（次表面散射近似）、鏡面反光、樹冠內部自遮蔽（按枝條深度預計算 AO）。逆光時葉片發亮是真實感的關鍵視覺特徵。
6. **LOD 分層**：
   - 近（< 30 m）：真實單片葉幾何（Mesh Shader 生成），完整風動
   - 中（30–150 m）：葉簇卡片（由近景模型渲染生成的葉簇紋理）
   - 遠（150 m – 2 km）：**八面體 Impostor**，執行時把程序化樹渲染成多角度貼圖集
   - 超遠：併入地形顏色 / 森林冠層高度場
7. **風**：分層風動畫（樹幹搖擺 → 枝條 → 葉片顫動），在頂點/網格著色器中計算，成本極低。

評估：**可行，難度高**。真實感主要取決於葉片形狀、透光、自遮蔽和 LOD 過渡的品質，需要大量調參迭代。

#### 3.5.2 草
- 由 Compute/Mesh Shader **每幀在鏡頭周圍即時生成草葉**（不佔記憶體）：每根草是 3–7 個頂點的彎曲帶狀，高度、彎曲度、顏色由噪聲和地形濕度決定。
- 密度隨距離衰減；遠處草由地形材質 + 「草地法線/顏色」接替，過渡處加入少量卡片草。
- 車輛壓過草地時寫入「交互貼圖」，草被壓倒並緩慢恢復，輪胎痕跡可見。
- 評估：**成熟技術（如《對馬島》方案），可行性高**。iOS 上需嚴格控制數量。

#### 3.5.3 花與灌木
- 花：參數化花瓣（極座標曲線 / 玫瑰線）+ 葉序（黃金角螺旋）排佈，作為草系統的實例變體散佈。
- 灌木：與樹共用枝幹/葉片生成器，參數不同。
- 評估：可行，難度中等。

### 3.6 車輛（第二難點）

- **車身**：「參數化截面放樣 + 細分曲面」——用一組參數（軸距、車頂線、腰線、輪拱、前後懸、進氣口…）描述車型，生成高品質曲面，再細分出網格。車型本質上是一段「描述造型的程式碼」，一輛車只有幾 KB。
- **細節**：車燈（程序化反光杯 + 透鏡折射）、輪轂（極座標函數，種類可以非常多）、輪胎（胎紋函數）、格柵、車窗、內飾（簡化）。
- **材質**：車漆（見 3.3）、玻璃、鍍鉻、碳纖維、橡膠，全部函數化。
- **風險**：參數化車身要「好看、像真車」需要大量造型調試，是美學難度而非技術難度。建議：先做少量（3–5 款）精心調校的原型車型，再開放參數組合。
- 評估：**技術可行，美術風險高**。注意：不能直接仿製真實品牌車型的外觀和名稱（版權/商標），建議原創車型。

### 3.7 物理與其他系統

| 系統 | 方案 | 可行性 |
|---|---|---|
| 車輛物理 | 自研：Pacejka 魔術公式輪胎 + 射線/圓柱體懸掛 + 傳動系統；固定 120–240 Hz 子步 | 高 |
| 碰撞 | 地形用高度場碰撞（極便宜）；樹幹用膠囊體；其餘用 Jolt Physics（開源、支援 Apple 平台） | 高 |
| 世界串流 | 按區塊（如 256 m）非同步生成：地形 → 植被分佈 → 碰撞 → 光追 BLAS，時間切片避免卡頓 | 中（工程量大） |
| 音頻 | 程序合成引擎聲（加法合成 + 顆粒合成）、輪胎聲、風聲；AVAudioEngine | 中 |
| 生成快取 | 磁碟快取已生成區塊，可隨時刪除重建 | 高 |

### 3.8 「降低性能要求」的總體策略

1. **生成與渲染分離**：函數只在區塊進入視野時執行一次，結果快取。
2. **GPU Driven + 激進剔除**：Mesh Shader 簇剔除、Hi-Z 遮擋剔除，只畫看得見的東西。
3. **低解析度渲染 + MetalFX 超分**（性能收益最大的單項）。
4. **光追只用在最值得的地方**（車身、玻璃、水面），其他用便宜近似。
5. **多級 LOD + 自動 Impostor**：遠景幾乎零幾何成本。
6. **TBDR 友好**：減少渲染目標讀寫，iPhone 功耗/發熱顯著下降。
7. **時域分攤**：反射探針、GI 探針、陰影遠級聯分幀更新。
8. **可變速率著色（如可用）/ 降低遠景著色頻率。**

### 3.9 安裝包體積估算

| 項目 | 估算 |
|---|---|
| 引擎與遊戲程式 | 30–60 MB |
| 預編譯著色器 | 20–50 MB |
| 字體、UI | 10–20 MB |
| 少量音頻樣本（如需要） | 0–50 MB |
| 地圖、車輛、植被、材質 | **< 1 MB（僅參數與種子）** |
| **合計** | **約 60–180 MB** |

執行時快取（可刪除）：約 1–4 GB，視遊玩過的區域而定。

## 4. 主要風險

| 風險 | 等級 | 應對 |
|---|---|---|
| 樹木真實感達不到預期 | 高 | 最早做植被垂直切片（單棵樹 → 小樹林 → 森林），先驗證再擴展 |
| 程序化車身不夠好看 | 高 | 少量精調車型；建立車型參數編輯器實時預覽 |
| iPhone 發熱降頻 | 中高 | 30 fps 模式、動態解析度、溫度感知自動降檔 |
| 區塊生成造成卡頓 | 中 | 非同步 + 時間切片 + 預測行駛方向預生成 |
| 程序化世界「重複、無趣」 | 中 | 侵蝕模擬、生態分佈規則、手工放置的「地標參數」 |
| 自研引擎工作量 | 高 | 嚴格分階段；以可玩原型驅動 |

## 6. 待用戶確認的問題

1. **車輛性能**（類型：公路跑車 / 越野 / 拉力；擬真程度：街機 ↔ 模擬）——待用戶說明
2. **地圖類型**（荒野 / 城市 / 混合）——待用戶說明。注意：**城市比荒野難很多**（建築程序化、路網規則、燈光數量），植被比重也會改變技術重點。
3. 世界大小期望？（參考：地平線 4 約 72 km²）
4. 最低支援設備是否接受「M1 / iPhone 13（A15）」？光追檔是否接受只在 M3 / iPhone 15 Pro 以上提供？
5. 幀率優先還是畫質優先？（尤其 iPhone：30 fps 高畫質 vs 60 fps 中畫質）
6. 是否接受自研引擎方案？團隊規模與圖形學經驗如何？
7. 是否需要多人/線上功能？是否需要晝夜與天氣？
8. 是否允許少量音頻樣本，還是聲音也要求全部程序合成？
